# Enterprise pilot brief

**Status:** proposed artifact, not a record of a completed pilot.

## Hypothesis

For a defined engineering team, a local-first context layer can reduce avoidable AI exploration while preserving acceptable task quality and privacy requirements.

## Pilot design

- Select a fixed set of representative repositories and coding tasks.
- Define the current workflow and comparison condition before access.
- Record setup time, supported tools, failures, retries, task quality, and usage cost.
- Hold model versions, prompts, permissions, and repository state constant where practical.
- Review weekly with both developer champions and the buying stakeholder.

## Decision criteria

**Expand** if task quality remains within the agreed threshold, setup is repeatable, and the buyer can identify a credible business case.

**Revise** if the workflow is valuable but missing requirements or support costs are too high.

**Stop** if the problem is not urgent, adoption is too fragile, privacy requirements cannot be met, or measured value is not distinguishable from normal variation.

No customer or pilot outcome is claimed here. Any reference to a named organization requires explicit authorization.
